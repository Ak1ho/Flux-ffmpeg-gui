# 流转 · Flux

Windows 本地媒体处理桌面应用。以用户提供的 Linear 设计稿为视觉依据，将 FFmpeg 9.0.1 和 QKKDecrypt 集成到同一 GUI。

## 开源仓库说明

仓库提交包含应用源码、测试、界面资源和解密适配器。Windows 版 FFmpeg 可执行文件接近 GitHub 单文件限制，因此不直接提交；发布包中的 `engines/` 目录包含运行所需文件，源码开发时请将 FFmpeg 9.0.1 的 `ffmpeg.exe`、`ffprobe.exe` 和 `ffplay.exe` 放入该目录，或在应用设置中指定外部 FFmpeg 目录。发布版请使用项目 Release 附件，不要把本地构建目录或 ZIP 归档提交到仓库。

## 2.0.4 · 批量入队与任务名称修正

- 批量添加文件、文件夹或拖入素材后，自动选中新导入的可见素材，不再只选中第一项；保留已有可见选择。可以手动选择子集，右侧显示本次处理数量。
- 普通批量每个选中素材独立入队，合并操作仍生成一个多输入任务；筛选隐藏的素材不会被意外加入。
- 队列操作名称按媒体类型区分，视频压缩、调整分辨率和合并视频不再显示成图片或音频操作。已有队列记录显示时也使用修正后的名称。

## 2.0.3 · 自绘下拉与滚轮防误改

- 全部参数下拉框、整数和小数输入框禁用滚轮改值，包括已获得输入焦点的控件。鼠标停在参数上滚动时，继续滚动所在页面，不会偷偷改变格式、质量或尺寸。
- 下拉列表使用独立自绘圆角深色浮层，紫蓝选中态、对勾、柔和悬停高亮和旋转箭头，不使用系统默认下拉菜单。
- 展开约 170 ms 淡入轻移，选定或 Esc 取消时约 110 ms 淡出收起；点击外部、窗口移动/隐藏或选项模型更新时立即安全关闭。关闭设置中的动效总开关后，下拉动效也关闭。
- 长列表可以用滚轮滚动，但浏览和悬停不提交参数。点击选项或按 Enter/Space 才确认；方向键、Home/End、PageUp/PageDown 浏览，Esc 取消，Tab 返回表单下一项。
- 数值仍可手工输入、使用上下按钮或键盘方向键调整。下拉框调整不会触发左侧导航文字转场。

## 2.0.2 · 可迁移资源路径

内置引擎、酷狗 key 和酷我签名文件改为 `@app/` 资源相对路径。例如 `@app/engines` 会在运行时解析到当前安装目录的 `_internal/engines`，不依赖启动时的工作目录。设置与任务快照也保存相对标记；旧版可识别的内置路径自动迁移，即使旧安装目录仍然存在，也不再调用旧副本。

请移动或复制整个 `Flux` 文件夹（包括 `_internal`），不要单独移动 EXE。自己选择的外部引擎、数据库、密钥、输入素材和输出目录保留实际位置；自定义引擎缺失会明确报错，不再静默换成内置引擎。软件不会猜测被移动素材的新位置。

本版是可移动的软件目录，不是数据随身模式：任务和设置仍保存在当前 Windows 用户的 `%LOCALAPPDATA%\MediaWorkbench`，不会随程序目录自动复制到另一台电脑。日志中的实际执行路径以及对话中的本机下载/打开链接可以是绝对路径，不作为持久化的内置资源定位方式。

## 2.0.1 · 新名称与图标

中文名「流转」，英文名「Flux」，寓意流动与变化，对应媒体格式之间的转换。使用深色圆角底、紫蓝播放符号和斜切留白组成的应用图标，统一用于窗口、侧栏、任务栏及 EXE 资源。原有动效与处理功能保留。

为兼容旧版，仍使用 `%LOCALAPPDATA%\MediaWorkbench` 保存任务、设置、预设及日志，继续识别 `MEDIAWORKBENCH_STATE` 环境变量；默认输出目录保持原路径，已保存的自定义位置不变。旧版成品不会被覆盖。

## V2 · 光影交互

- 保留原有 Linear 深色布局与全部媒体处理流程。
- 软件客户区任意位置的紫蓝光晕随鼠标移动，照亮附近文字；图片区不会被误当作文字加辉光。
- 点击产生双层扩散水波，不拦截原有点击、输入、拖放和选择。
- 仅左侧导航切页时，旧文字向上收起，新文字轻弹出现；卡片和面板不整体飞入。
- 设置 → 光影与动效：总开关、三个分项开关、30–150% 光效强度，即时预览，保存后持久化。
- 动效使用原生 Qt 绘制，不引入浏览器运行时；鼠标静止且水波/转场结束后停止动效计时器。Windows 原生标题栏、系统文件对话框及弹出菜单不绘制光效。

## 启动

直接打开成品目录中的 `Flux.exe`。成品自带 Python、Qt、FFmpeg 与解密运行资源，不需要安装 Python、Node.js 或配置 PATH。移动软件时请移动整个成品目录，不能单独取出 EXE。

源代码启动：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

## 功能

- 视频：格式转换、压缩、截取、调整分辨率、裁剪、旋转/翻转、变速、静音、提取音频、GIF、提取帧、合并、水印、烧录字幕、无损换封装。
- 音频：转换、截取、响度标准化、音量增益、保音调变速、淡入淡出、降噪、合并。
- 图片：格式转换、压缩、缩放、裁剪、旋转/翻转；静态图片操作处理首帧。
- 音乐解密：调用提供的 QKKDecrypt 原适配器，支持解密后继续转码。
- 统一队列：1–4 并发媒体任务，解密串行；进度、日志、取消、重试、暂停派发、历史持久化、任务报告。
- 文件拖放、目录递归导入、分类筛选、搜索、多选、排序、媒体探测、缩略图、播放预览、参数预设。

详见 `使用说明.md`。

## 目录

```text
app.py             GUI / 工作进程双入口
studio/            自有界面、任务调度与媒体处理代码
engines/           用户提供的 FFmpeg、酷狗 key 和原生 DLL
vendor/qkk/src/    用户提供的 QKKDecrypt 源码，未改写其解密算法
licenses/          原项目、Qt/PySide6、Frida、psutil、Pillow 等声明
tests/             实际 FFmpeg、队列与 GUI 自动化测试
```

设置与日志保存在 `%LOCALAPPDATA%\MediaWorkbench`；媒体默认输出到 `%USERPROFILE%\Downloads\MediaWorkbench`。

## 构建与验证

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
python build.py --dist .\release --work .\build-work
```

构建为可替换动态库的 onedir 目录，不使用 onefile 自解压。`engines` 与许可证位于成品的 `_internal` 目录中。

## 已知边界

- QQ / 酷我需要相应客户端保持运行，且引擎必须兼容客户端版本；不能承诺任意版本都可解密。
- 酷狗 KGG 需要匹配的本地 `KGMusicV3.db`。其他酷狗格式使用原项目 key 资源。
- 本版本只接入原目录实际提供的格式，不将 QMC、NCM 等未实现格式标注为已支持。
- 此应用不是多轨剪辑器，也不是全部 FFmpeg 命令行开关的机械映射。常用输出格式已做实际测试；输入能力受所提供构建限制。
- 普通处理使用首条视频及首条音轨。无损换封装保留视频/音轨，不保留字幕、附件及数据流；目标容器必须兼容源编码。
- 单遍响度标准化不等于两遍精确母带测量。转为 FLAC/WAV 不会将有损源变成真正无损原音。
- 硬件编码依赖驱动/显卡；不提供假成功回退。失败可改用自动软件编码重试。
- 成品未做代码签名；首次运行可能出现 Windows 或安全软件提示。不需要关闭系统防护，先核验文件来源。
